How to read this note

  • Part 1 — small changes. 19 points. Each is marked on the screen itself. These are changes of wording, order or placement. None needs a new screen or new data.
  • Part 2 — new sections. 10 proposals for sections that do not exist today. These need development work, and are offered for GAD to decide on before NIC is approached.
  • Effort shown against each point is our reading of the screens, not NIC's estimate. NIC is best placed to confirm it.

Part 2 — Sections that could be added

These do not exist today. They follow from the way the APAR process is being organised — four monitoring levels (custodian, cadre monitoring authority, service monitoring authority, GAD and the ACS) and four user windows (officer, reporting authority, reviewing authority, custodian). Each needs development work, so these are for GAD to consider before approaching NIC.

S1

One stage strip on every screen

For: All four monitoring levels · all four user windows
What is missing today

Each screen counts APARs differently — generated, closed, partially completed, workflow created. None shows the cycle as the six stages that the GR describes.

Section proposed

A single strip at the top of every dashboard and every user window: Self-appraisal → Reporting → Reviewing → Disclosure → Representation → Closed, with the count and the closing date under each stage. The same strip everywhere, filtered to whatever the user is allowed to see.

Indicative form
Self-appraisal1,109 of 1,197closed 31 May
Reporting612 of 1,197due 31 Jul
Reviewing—due 30 Sep
Disclosure—due 31 Oct
Representation—15 days
Closed—30 Nov
Why: Custodian, cadre authority, service authority and ACS then read the same picture. An officer sees where their own APAR sits in the same six boxes.Effort: Moderate · one component, reused
S2

Show how long APARs have been pending, not only how many

For: Cadre monitoring authority · service monitoring authority · GAD
What is missing today

Pendency is shown as a count. A count does not say whether the delay is of a week or of four months, so it does not say where to intervene.

Section proposed

Add age bands beside each pendency figure: 0–15 days · 16–30 · 31–60 · over 60. The dates needed are already recorded against each stage.

Indicative form
REGION0–15 d16–30 d31–60 dOver 60 d
MH-LR-AURANGABAD129145
MH-LR-NASHIK31600
Same totals as today, separated by how long they have been waiting.
Why: A region with 40 APARs pending for 60 days and one with 40 pending for a week need different action. At present they look the same.Effort: Low to moderate · a date difference on existing fields
S3

An ‘action required by you’ block at the top of every user window

For: Officer · reporting authority · reviewing authority · custodian
What is missing today

Each window opens on counts and system information. None opens on what the user has to do, or by when.

Section proposed

A single block at the top of each window: what is due from this user, how many, and the date. One line per item, each opening the relevant form.

Indicative form
Action required by you
Your self-appraisal for 2025-26due in 4 days
12 assessments as reporting authoritydue 31 Jul
3 reviews as reviewing authoritydue 30 Sep
Why: Most delay is not refusal; it is not knowing an action is due. This is the cheapest way to reduce pendency.Effort: Low to moderate · uses counts the system already holds

Features that should be kept as they are

Noted so that they are not changed while the points above are taken up.

Opening a figure into the list of officers

A regional figure opens into the named officers behind it, with Excel and CSV. This is what makes the dashboard usable, and it already works.

The four-step workflow wizard

Numbered steps, bulk selection, and Not Started / In Process / Completed filters. A sound pattern, worth using on other multi-step screens.

The DPC report's method note

The report states how the weighted grade is worked out, and lets the user hover to see which earlier years were used. Useful for a report placed before a committee.
